SPÉCIFICATIONS TECHNIQUES - APPLICATION CARTOGRAPHIE TERRE DU MILIEU
VUE D'ENSEMBLE
Application web de cartographie interactive pour jeux de rôle basés sur la Terre du Milieu. Permet la gestion de lieux, régions, voyages et quêtes avec synchronisation cloud via authentification Google.

ARCHITECTURE GLOBALE
Stack Technique
Frontend: HTML5, CSS3 (Tailwind), JavaScript ES6+ modulaire
Backend: Python Flask avec SQLite
Authentification: Google OAuth 2.0
IA: Google Gemini API pour génération de contenu
Stockage: Cloud (base SQLite) + localStorage (cache)
Structure des Fichiers
/js/managers/          # Modules fonctionnels
/js/utils/            # Utilitaires et constantes
/images/              # Assets statiques
/uploads/             # Fichiers utilisateurs (organisés par google_id)
/templates/           # Templates HTML
app.py                # Serveur Flask
index.html            # Application principale
login.html            # Page de connexion
PRINCIPES D'ORGANISATION DU CODE
Architecture Modulaire par Managers
Chaque fonctionnalité est isolée dans un manager dédié avec responsabilité unique:

DataManager: Gestion des données (lieux, régions)
AuthManager: Authentification Google et synchronisation cloud
FilterManager: Filtrage et affichage des éléments
VoyageManager: Création et gestion des voyages
PathManager: Calculs de distances et chemins
SettingsManager: Configuration et cartes multiples
InfoBoxManager: Affichage détaillé des éléments
ImportExportManager: Import/export JSON avec fusion intelligente
ZoomManager: Navigation et zoom sur carte
PositionManager: Marqueur de position des aventuriers
JournalManager: Journal de voyage
AdventureManager: Gestion des quêtes et rumeurs
CalendarManager: Calendrier personnalisé
GeminiManager: Intégration IA pour génération de contenu
UploadManager: Gestion des uploads d'images
LibraryManager: Bibliothèque d'images utilisateur

Flux de Données
Chargement Initial

Vérification authentification Google
Si authentifié: chargement données cloud → localStorage (cache)
Si non authentifié: redirection vers login
Synchronisation Cloud

Source unique de vérité: données cloud
localStorage utilisé comme cache uniquement
Synchronisation manuelle uniquement (bouton sync)
Détection et résolution de conflits côté serveur
Import/Export

Import: fusion intelligente avec données existantes
Sauvegarde automatique cloud après import
Export: format JSON complet avec métadonnées
PRINCIPES DE DÉVELOPPEMENT
Gestion de l'État
Variables globales exposées via window pour communication inter-managers
Fonction markAsUnsaved() pour signaler modifications
Fonction scheduleAutoSync() désactivée (sync manuelle uniquement)
Persistance des Données
Cloud (prioritaire): Données utilisateur dans SQLite via API REST
LocalStorage (cache): Copie locale pour performances
Migration automatique: Ajout mapId aux anciens éléments
Structure des Données
Location:

{
  id, name, description, color, coordinates: {x, y},
  mapId, known, visited, images: [{url, type}],
  Rumeurs: [], Tradition_Ancienne, Evenements_Voyage: []
}
Region:

{
  id, name, description, color,
  coordinates: [{x, y}] ou points: [{x, y}],
  mapId, known, visited
}
Voyage:

{
  id, path: [{x, y}], distance, date, discoveries,
  segments: [{distance, terrain, discoveries}]
}
Cartes Multiples
Système multi-cartes avec mapId
Filtrage automatique par carte active
Migration automatique des anciens éléments

POINTS D'ATTENTION DÉVELOPPEMENT
Toujours synchroniser  et 
Nettoyer flags localStorage après utilisation (calendar_from_cloud, adventurers_position_from_cloud)
Désactiver isAuthenticated temporairement lors de applyContextData()
Utiliser scheduleAutoSync() pour déclencher sync (actuellement désactivée)
Vérifier mapId lors du rendu (filtrage par carte active)
Gérer conflits de sync avec timestamps et choix utilisateur
