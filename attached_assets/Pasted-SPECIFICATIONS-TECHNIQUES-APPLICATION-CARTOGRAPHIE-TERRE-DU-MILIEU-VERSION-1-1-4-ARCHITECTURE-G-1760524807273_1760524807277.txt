SPECIFICATIONS TECHNIQUES - APPLICATION CARTOGRAPHIE TERRE DU MILIEU

VERSION: 1.1.4

ARCHITECTURE GLOBALE

Application web de cartographie interactive pour jeu de role Terre du Milieu
Architecture client-serveur avec backend Flask Python et frontend JavaScript modulaire
Base de donnees SQLite pour persistance utilisateur
Authentification Google OAuth 2.0 obligatoire

STRUCTURE BACKEND

Serveur Flask sur port 8080
Routes principales:

/login: Page authentification
/: Application principale (requiert auth)
/api/auth/user: Verification statut utilisateur
/api/user/data: GET/PUT donnees utilisateur cloud
/auth/google: Initiation OAuth
/auth/google/callback: Retour OAuth
/auth/logout: Deconnexion
Base de donnees SQLite:

Table users: id, google_id, email, name, created_at
Table travel_contexts: id, user_id, name, data_json, shared, share_token, created_at, updated_at
Table api_usage: id, user_id, endpoint, tokens_used, created_at
STRUCTURE FRONTEND

Architecture modulaire JavaScript:

main.js: Point entree, orchestration
Managers (js/managers/): Modules specialises
MANAGERS PRINCIPAUX

AuthManager:

Gestion authentification Google OAuth
Synchronisation cloud automatique
Collecte et application donnees contexte
Detection modifications non sauvegardees (flag hasUnsavedChanges)
Icone cloud visible uniquement si modifications non sauvegardees
Synchronisation manuelle via icone cloud
DataManager:

Chargement initial structure vide (pas de localStorage ni URL)
Sauvegarde locale lieux et regions
Appel scheduleAutoSync apres modifications
ImportExportManager:

Export unifie lieux et regions format JSON
Import avec modes remplacer/fusionner
Gestion rumeurs multiples par lieu
Support regions comme lieux type "region"
SettingsManager:

Gestion cartes disponibles
Descriptions aventuriers et quete
Styles narration (brief, detailed, keywords)
Parametres calendrier
Integration UploadManager et GeminiManager
Appel markAsUnsaved() apres changement parametres
VoyageManager:

Tracage voyages sur carte
Calcul distances (3 pixels = 1 mile)
Detection regions traversees
Lieux a proximite (50 miles)
CalendarManager:

Gestion saisons et dates
Mode saison simple ou calendrier detaille
12 mois avec meteo quotidienne
Appel markAsUnsaved() apres changement date/saison
PositionManager:

Gestion marqueur position aventuriers
Sauvegarde position avec flag cloud
Restauration prioritaire depuis cloud
Appel markAsUnsaved() apres deplacement manuel
JournalManager:

Stockage entrees voyage localStorage
Generation via Gemini API
Appel markAsUnsaved() apres nouvelle entree
REGLES SYNCHRONISATION CLOUD

Chargement initial:

Authentification Google obligatoire (redirection /login si non auth)
Verification statut via /api/auth/user
Chargement donnees cloud via GET /api/user/data
Nettoyage localStorage existant (cloud source unique)
Application donnees cloud via applyContextData()
Sauvegarde cache localStorage
Rendu lieux et regions
Flag hasUnsavedChanges = false
Modification locale:

Changement utilisateur (creation lieu, deplacement marqueur, etc.)
Sauvegarde localStorage immediate
Appel markAsUnsaved() pour afficher icone cloud
Flag hasUnsavedChanges = true
Synchronisation cloud:

Clic icone cloud ou scheduleAutoSync (debounce 2 secondes)
Collecte donnees via collectCurrentContextData()
Envoi PUT /api/user/data avec timestamp
Detection conflits via comparaison timestamps
Resolution conflits (garder local ou charger cloud)
Appel markAsSaved() apres succes
Affichage message "Synchronisation effectuee"
Masquage icone cloud
Elements synchronises:

Lieux (locations)
Regions (regions)
Calendrier (currentSeason, currentCalendarDate, calendarData, isCalendarMode)
Parametres (availableMaps, activeMapUrl, partyDescription, questDescription, narrationStyle)
Journal (travelJournal)
Position marqueur (adventurers_position)
Filtres (activeFilters)
